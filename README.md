# 군 생활 도우미

전역일 D-day, 휴가·외박 일정, 그룹 근무표를 관리하는 웹 서비스입니다.
Next.js(App Router) + Supabase(PostgreSQL, 로그인, Realtime)로 만듭니다.

## 진행 단계

| 단계 | 내용 | 상태 |
| --- | --- | --- |
| 3-1 | DB 스키마 (`supabase/schema.sql`) | 완료 |
| 3-2 | 앱 골격, 로그인, 복무 정보 설정, 홈 D-day | 코드 작성 완료 (아직 실행 확인 전) |
| 3-3 | 휴가·외박·외출 일정과 달력 (`/calendar`) | 코드 작성 완료 (아직 실행 확인 전) |
| 3-4 | 그룹, 희망 근무 신청, 근무표, 실시간 반영 (`/groups`, `/groups/[id]`) | 코드 작성 완료 (아직 실행 확인 전) |
| 3-5 | PWA 설정(아이콘, 매니페스트, 서비스 워커), 배포 가이드 (`DEPLOY.md`) | 완료 (배포는 아직 안 함) |
| 4 | 검수: DB 규칙 보강, 화면 수정 | 코드 검수 완료, 배포 후 점검표(`DEPLOY.md`) 대기 |

## 처음 실행하는 순서

1. Supabase에서 새 프로젝트를 만든다.
2. SQL Editor에 `supabase/schema.sql` 전체를 붙여 넣고 한 번 실행한다.
3. Authentication 설정에서 개발 중에는 이메일 확인(Confirm email)을 꺼 두면 가입 직후 바로 로그인된다.
   켜 두면 확인 메일의 링크를 눌러야 로그인할 수 있다.
4. Project Settings > API 에서 URL과 anon key를 복사한다.
5. 로컬에서 실행하는 경우: `.env.local.example`을 `.env.local`로 복사해 값을 채우고
   `npm install`, `npm run dev`를 실행한다.
6. 배포하는 경우: GitHub에 push하고 Vercel에서 저장소를 가져온다. 같은 두 환경 변수를
   Vercel 프로젝트 설정에 넣는다. 빌드는 Vercel 서버에서 하므로 사지방 PC에 설치가 필요 없다.

## 테스트

날짜 계산, 충돌 판정, 실시간 변경 반영, PWA 파일 검증은 의존성 없이 테스트할 수 있다.
Node 22 이상에서 `npm test`. 배포 방법과 배포 후 점검표는 `DEPLOY.md`에 있다.

## 알려진 한계 (4단계 검수에서 다룰 항목)

- 일정의 공개 범위를 '그룹에 공개'에서 '나만 보기'로 바꾸면, 다른 구성원의 열려 있는 화면에는
  새로고침하기 전까지 그 일정이 남을 수 있다. (실시간 알림은 볼 권한이 있는 행만 보낸다)
- 초대 코드는 8자리(16진수)이고 무작위로 대입하는 시도를 막는 횟수 제한이 없다. 소규모로 쓰기에는 충분하지만,
  공개 서비스로 키우기 전에 제한을 추가한다.
- 실시간 반영은 Supabase 프로젝트에서 `schema.sql`의 마지막 부분(Realtime 설정)이 적용돼야 동작한다.
  실제로 두 기기에서 열어 확인하는 것이 필요하다.
- DB 규칙은 임시 PostgreSQL에서 시나리오별로 검증했다. 화면 코드는 로직 테스트(`npm test`)와 타입 점검까지만
  거쳤고, 브라우저에서 실행해 본 적은 없다.

## 안전 규칙

실명, 계급, 군번, 부대명, 작전·훈련 일정 등 부대 내부 정보는 입력하지 않는다.
실제 부대에서 쓰기 전에 부대 보안 규정으로 허용되는지 직접 확인한다.
